# Redis

## Redis 是什么
Redis 是一个开源的、非关系型数据库，用于存储和检索数据。

- 内存存储数据库
- 特点：
  - 支持设置过期时间
  - 支持限定占用空间

## 安装 Redis

版本号的奇数表示开发版本，偶数表示稳定版本。

官方不支持Windows系统。平替是[`Memurai`](https://www.memurai.com/)。

## Redis 数据库
Redis 数据库是存储数据的容器，默认有16个数据库，每个数据库可以包含多个键值对（key-value）。每个键值对都有一个唯一的键（key）和一个值（value）。

- 数据库：Redis 数据库是存储数据的容器，每个数据库可以包含多个键值对（key-value）。
- 键值对：Redis 键值对是存储数据的基本单位，每个键值对都有一个唯一的键（key）和一个值（value）。

## 基础操作
```shell
# 连接到Redis服务器
redis-cli

# 断开Redis连接
quit

# 测试Redis服务器是否可用，正常返回 PONG
ping

# 启动并指定ip地址和端口号
redis-cli -h 127.0.0.1 -p 6379

# 查看服务器状态
# section 可选参数，指定要查看的服务器状态部分，可选值为：
#   - general：查看一般服务器状态
#   - memory：查看内存使用情况
#   - persistence：查看持久化状态
#   - server：查看服务器状态
#   - clients：查看客户端连接状态
#   - commands：查看命令统计
#   - keyspace：查看键空间状态
#   - db：查看数据库状态
info [section]

# 切换数据库
select db_index

# 移动键值对到指定数据库
move key db_index

# 清空当前数据库
flushdb

# 清空所有数据库
# 注意：此操作会删除所有键值对，操作后数据库将为空
flushall
```

## 数据类型
Redis 支持多种数据类型，包括：
- 字符串（String）：其他数据类型的基础类型
- 列表（List）：一种有序的字符串列表，每个元素都有一个索引（索引从0开始）。
- 集合（Set）：一种无序的字符串集合，每个元素都是唯一的。
- 有序集合（ZSet）：一种有序的字符串集合，每个元素都有一个分数（score），分数可以是浮点数。
- 哈希（Hash）：一种嵌套的键值对结构，非常适合存储对象类型的数据。

### 常用数据操作命令

简单约定：
- 所有Redis命令都是大写字母组成

```shell
# 设置键值对
SET key value

# 批量设置键值对
MSET key1 value1 key2 value2 ...

# 查看所有键名
KEYS *

# 将指定键的值设置为新值并且返回该键的旧值
GETSET key value

# 获取键值对的值
GET key

# 批量获取键值对的值
MGET key1 key2 ...

# 删除键值对或批量删除键值对
DEL key1 key2 ...

# 查看键值对是否存在
EXISTS key

# 查看键值对的过期时间
TTL key

# 设置键值对的过期时间
EXPIRE key seconds

# 获取键值的类型
TYPE key

# 获取键值的长度
STRLEN key

# 重命名键值对
RENAME old_key new_key
```

### 集合数据结构

集合可以理解为一个无序的、元素唯一的容器：

```text
┌──────────────────────────────────────────┐
│  key: "tags"                            │  ← 外层键（集合名）
├──────────────────────────────────────────┤
│  ┌──────────────────────────────────┐   │
│  │  "Redis"                         │   │
│  │  "数据库"                         │   │
│  │  "缓存"                           │   │
│  │  "NoSQL"                         │   │
│  │  "内存存储"                       │   │
│  └──────────────────────────────────┘   │
└──────────────────────────────────────────┘
```

#### 核心特点

1. **无序性**：集合中的元素没有固定顺序
2. **唯一性**：集合中的元素不能重复，自动去重
3. **高效操作**：添加、删除、查找的时间复杂度为 O(1)
4. **集合运算**：支持交集、并集、差集等数学集合操作

#### 常用命令

```shell
# 添加元素（可一次添加多个）
SADD tags "Redis" "数据库" "缓存"

# 获取集合所有元素
SMEMBERS tags
# 返回: ["Redis", "数据库", "缓存"]

# 检查元素是否在集合中
SISMEMBER tags "Redis"   # 返回 1（存在）
SISMEMBER tags "MySQL"   # 返回 0（不存在）

# 删除元素
SREM tags "缓存"

# 获取集合大小
SCARD tags

# 随机返回一个元素（不删除）
SRANDMEMBER tags

# 随机返回多个元素（不删除）
SRANDMEMBER tags 2

# 随机返回并删除一个元素
SPOP tags

# 获取两个集合的交集
SINTER tags1 tags2

# 获取两个集合的并集
SUNION tags1 tags2

# 获取两个集合的差集（在tags1中但不在tags2中）
SDIFF tags1 tags2

# 将交集/并集/差集结果存储到新集合
SINTERSTORE result tags1 tags2
SUNIONSTORE result tags1 tags2
SDIFFSTORE result tags1 tags2
```

#### 适用场景

- **标签系统**：文章标签、用户兴趣标签
- **去重统计**：独立访客（UV）、独立IP统计
- **好友关系**：共同好友、推荐好友
- **权限管理**：用户角色、权限集合
- **黑名单/白名单**：IP黑名单、用户白名单


### 有序集合数据结构

有序集合可以理解为一个带有分数权重的排行榜，元素按分数自动排序：

```text
┌──────────────────────────────────────────┐
│  key: "leaderboard"                     │  ← 外层键（集合名）
├──────────────────────────────────────────┤
│  ┌──────────────┬─────────────────────┐  │
│  │   分数(score) │    成员(member)    │  │
│  ├──────────────┼─────────────────────┤  │
│  │    100.0     │    "张三"           │  │  ← 排名第1
│  │     95.0     │    "李四"           │  │  ← 排名第2
│  │     90.0     │    "王五"           │  │  ← 排名第3
│  └──────────────┴─────────────────────┘  │
└──────────────────────────────────────────┘
```

#### 核心特点

1. **有序性**：元素按照分数（score）自动排序
2. **唯一性**：集合中的元素是唯一的，但分数可以相同
3. **快速操作**：支持 O(log N) 复杂度的插入、删除和查找
4. **双重排序**：分数相同时按字典序排序

#### 常用命令

```shell
# 添加元素（分数 + 成员）
ZADD leaderboard 100 "张三" 95 "李四" 90 "王五"

# 获取排名（从低分到高分，索引从0开始）
ZRANK leaderboard "李四"   # 返回 1

# 获取倒序排名（从高分到低分）
ZREVRANK leaderboard "张三"   # 返回 0

# 获取分数
ZSCORE leaderboard "张三"   # 返回 "100"

# 获取前N名（按分数升序，带分数）
ZRANGE leaderboard 0 2 WITHSCORES
# 返回: ["王五", "90", "李四", "95"]

# 获取前N名（按分数降序，带分数）
ZREVRANGE leaderboard 0 2 WITHSCORES
# 返回: ["张三", "100", "李四", "95", "王五", "90"]

# 获取分数范围内的元素
ZRANGEBYSCORE leaderboard 90 100 WITHSCORES
# 返回: ["王五", "90", "李四", "95", "张三", "100"]

# 增加分数
ZINCRBY leaderboard 5 "王五"   # 王五分数变为 95

# 删除元素
ZREM leaderboard "李四"

# 获取集合大小
ZCARD leaderboard

# 获取分数范围内的元素数量
ZCOUNT leaderboard 80 100
```

#### 适用场景

- **排行榜**：游戏分数排名、积分排行榜
- **带权重的任务队列**：按优先级处理任务
- **范围查询**：获取分数在某个区间的元素
- **时间序列数据**：用时间戳作为分数进行排序

#### 与普通集合对比

| 特性 | 普通集合（Set） | 有序集合（ZSet） |
|------|----------------|------------------|
| **有序性** | 无序 | 按分数有序 |
| **排序方式** | 无 | 自动按分数排序 |
| **命令前缀** | S（如 SADD） | Z（如 ZADD） |
| **适用场景** | 去重、交集并集 | 排行榜、优先级队列 |

### 哈希数据结构

哈希可以理解为一个小型的表格或对象，包含多个 field-value 对：

```text
┌─────────────────────────────────┐
│  key: "user:1001"              │  ← 外层键（散列名）
├─────────────────────────────────┤
│  ┌──────────┬───────────────┐  │
│  │ field    │ value         │  │  ← 内层字段-值对
│  ├──────────┼───────────────┤  │
│  │ name     │ "张三"        │  │
│  │ age      │ "25"          │  │
│  │ email    │ "zhangsan@xx" │  │
│  └──────────┴───────────────┘  │
└─────────────────────────────────┘
```

#### 哈希核心特点

1. **层级结构**：一个散列包含多个 `field-value` 对
2. **高效存储**：相比使用多个独立 key，散列更节省内存
3. **原子操作**：可以对单个字段进行读写，不影响其他字段

#### 哈希常用命令

```shell
# 设置多个字段
HSET user:1001 name "张三" age 25 email "zhangsan@example.com"

# 获取单个字段
HGET user:1001 name   # 返回 "张三"

# 批量获取多个字段
HMGET user:1001 name age email
# 返回: ["张三", "25", "zhangsan@example.com"]

# 获取所有字段和值
HGETALL user:1001
# 返回: ["name", "张三", "age", "25", "email", "zhangsan@example.com"]

# 修改单个字段
HSET user:1001 age 26

# 删除字段
HDEL user:1001 email

# 批量删除字段
HDEL user:1001 name age

# 删除整个哈希
DEL user:1001

# 获取所有字段名
HKEYS user:1001

# 获取所有字段值
HVALS user:1001

# 获取字段数量
HLEN user:1001

# 检查字段是否存在
HEXISTS user:1001 name
```

#### 哈希适用场景

- 存储对象（用户、商品、配置等）
- 缓存结构化数据
- 计数器（如文章点赞数、评论数）

#### 哈希与普通字符串对比

| 方式 | 特点 |
|------|------|
| `SET user:1001 '{"name":"张三","age":25}'` | 存储JSON字符串，修改需完整读取和写入 |
| `HSET user:1001 name "张三" age 25` | 直接操作字段，更灵活高效 |

### 列表数据结构

列表可以理解为一个双向链表，支持从两端进行操作：

```text
┌──────────────────────────────────────────┐
│  key: "messages"                        │  ← 外层键（列表名）
├──────────────────────────────────────────┤
│  ┌────┬──────────────────────────────┐  │
│  │ 0  │ "第一条消息"                  │  │  ← 头部（左侧）
│  ├────┼──────────────────────────────┤  │
│  │ 1  │ "第二条消息"                  │  │
│  ├────┼──────────────────────────────┤  │
│  │ 2  │ "第三条消息"                  │  │
│  ├────┼──────────────────────────────┤  │
│  │ 3  │ "第四条消息"                  │  │  ← 尾部（右侧）
│  └────┴──────────────────────────────┘  │
└──────────────────────────────────────────┘
```

#### 核心特点

1. **有序性**：元素按照插入顺序排列，支持索引访问（从 0 开始）
2. **双向链表**：支持从头部（左侧）和尾部（右侧）进行操作
3. **允许重复**：列表中的元素可以重复
4. **高效操作**：两端插入和删除的时间复杂度为 O(1)

#### 常用命令

```shell
# 从左侧推入元素（头部）
LPUSH messages "第一条消息"

# 从右侧推入元素（尾部）
RPUSH messages "第二条消息" "第三条消息"

# 从左侧弹出元素（头部）
LPOP messages   # 返回 "第一条消息"

# 从右侧弹出元素（尾部）
RPOP messages   # 返回 "第三条消息"

# 获取指定范围的元素（包含两端）
LRANGE messages 0 -1   # 返回所有元素
LRANGE messages 0 2    # 返回前3个元素

# 通过索引获取元素
LINDEX messages 1   # 返回索引为1的元素

# 获取列表长度
LLEN messages

# 设置指定索引的值
LSET messages 0 "新消息"

# 在指定元素前后插入
LINSERT messages BEFORE "第二条消息" "插入的消息"

# 修剪列表（保留指定范围的元素）
LTRIM messages 0 9   # 只保留前10个元素

# 删除指定元素（count > 0 从头开始，< 0 从尾开始，= 0 删除所有）
LREM messages 1 "第二条消息"   # 删除第一个匹配的元素
```

#### 适用场景

- **消息队列**：使用 LPUSH + RPOP 实现队列
- **最近浏览记录**：使用 LPUSH + LTRIM 保留最近 N 条记录
- **栈结构**：使用 LPUSH + LPOP 实现栈
- **分页数据**：使用 LRANGE 获取指定范围的数据
- **时间线**：存储按时间排序的动态、日志等

#### 列表作为队列和栈

| 数据结构 | 推入操作 | 弹出操作 | 特点 |
|---------|---------|---------|------|
| **队列（FIFO）** | LPUSH | RPOP | 先进先出 |
| **栈（LIFO）** | LPUSH | LPOP | 后进先出 |

## 注意事项
1. 不同应用的数据应该储存在不同的Redis实例中，如应用A的数据储存在端口6379的Redis实例，应用B的数据储存在端口6380的Redis实例。
